# M3 聊天读取实施契约

## 1. 范围与边界

实现 `chat.conversations`、`chat.messages` 和 `chat.sync`。前两者仅查询当前账号的 SQLite；后者由 Agent 显式触发，经 `chatRead` 队列，复用页面已有聊天连接。禁止新建 IM 连接、后台轮询、自动换 token 或重试。真实发送不在本阶段内。

## 2. 数据契约

- 消息：`sourceId`、`sessionId`、`senderId`、`text`、`sentAt`；可选 `itemId`、`peerUserId`。来源 ID 不得用收到时间或随机数代替。
- 账号由 host 当前连接绑定，不接受页面任意指定的账号作为落库权限。
- `chat.messages` 接受 `sessionId` 或 `tag`（至少一个）、`afterSeq`、`limit`，返回 `items`、`nextAfterSeq`、`hasMore`。
- `chat.conversations` 接受 `tag`、`itemId`、`updatedAfter`、`limit`，按更新时间及会话 ID 稳定排序。分页设计在实现前明确，不允许静默截断。
- 未登录返回 `LOGIN_REQUIRED`，不能查询匿名账号下的数据。

## 3. 持久化与交付

- 数据库迁移到版本 3，保留版本 2 的事件、请求、缓存和调度记录。高版本拒绝启动。
- `chat_messages` 按 `(account_id, source_id)` 去重；本地 `seq` 使用 SQLite 整数，公共 JSON 使用十进制字符串。
- 消息、会话更新和 `chat.message` 事件在同一事务提交；提交后才 ACK 和推送 SSE。重复投递可 ACK，不生成第二条事件。
- 扩展使用持久 outbox，按账号隔离，条数和字节双重上限；ACK 丢失可重投。溢出必须持久标记同步缺口，提示主动 `chat.sync`，不能静默丢弃。
- 账号切换时旧账号消息不得转标新账号；旧连接 ACK 不得删除新连接记录。

## 4. 故障矩阵与验收

| 动作 | 状态与可见结果 | 副作用 |
| --- | --- | --- |
| 首次接收消息 | 本地查询和 SSE 返回同一 seq | 一次事务、一条事件 |
| 重复接收、ACK 丢失重投 | 返回已有结果 | 无重复事件 |
| 落库失败 | 不发送 ACK | outbox 保留，可恢复 |
| host 重启 | 消息及游标保留 | 不重新访问平台 |
| 切换账号后查询 | 仅当前账号记录 | 不泄漏旧消息 |
| outbox 达到上限 | 同步缺口可见 | 不无限增长 |
| 无页面或无已有 socket 同步 | `PAGE_NOT_READY` | 不自行建连 |
| 同步触发风控或登录失效 | 明确错误与风险信号 | 不重试 |
| 非法消息或超限正文 | 失败关闭或明确拒绝 | 不落原始帧或秘密 |

## 5. 实施顺序

1. 声明式参数和消息验证器、迁移与仓库测试。
2. 持久 outbox、落库 ACK 与重连测试。
3. 页面被动监听和显式同步接入，补真实 host 集成及页面测试。
4. 离线完整回归、构建、部署后受控只读 E2E。Mock 不替代真实消息验收。

阶段通过前不把相关方法列入 capabilities。M4 写操作和 M5 发布继续沿用统一 operations 表和未知结果不重放契约，不属于本阶段完成声明。

## 6. 细化约束

- 会话查询增加 `afterId`，按本地不可变 `row_id` 升序分页；`updatedAfter` 仅筛选，不把可变更新时间作为游标。输出 `nextAfterId` 与 `hasMore`。调用者需要最新活跃排序时，在完整分页后自行排序。
- 消息 ID、会话 ID、发送者 ID 均为最多 128 字符的非空字符串；正文最多 20000 字符，单消息 JSON 的 UTF-8 大小最多 64 KiB。时间为非负安全整数。拒绝未知字段，不保存原始 WebSocket 帧。
- outbox 采用串行写队列，单账号最多 1000 条、总编码大小最多 4 MiB。先持久化再投递。落库 ACK 绑定账号和来源 ID，只有持久删除完成后才从内存移除；删除失败保留并允许去重重投。
- 溢出时保留已有记录并持久记录 `syncRequired`。缺口信号不能因为重连或清空内存消失；只有一次明确成功的同步覆盖缺口后才允许清除。
- 本轮代理分工：协议校验与测试、数据库迁移与测试、页面聊天只读取证；写集合互不重叠。主代理整合并完成真实入口验证。

## 8. 扩展存储权限

为持久 outbox 增加 `storage` 权限，仅使用 `chrome.storage.local`。初始化时设置 `TRUSTED_CONTEXTS` 访问级别，不向 content script 暴露聊天存储，不使用浏览器云同步。存储读写异常必须保留错误状态，不能回退内存成功。权限白名单和构建产物检查同步更新。
- native 交付与 ACK 已接入：Host 核对当前账号并事务提交后 ACK；重复交付返回同一事件序号；错误方向、错误账号、落库失败均失败关闭且不 ACK。
- 扩展握手后重投当前账号 outbox，旧 Port 或账号不匹配 ACK 不删除记录；异步存储错误固定分类记录，不输出正文或原始异常。
- 交付链定向测试 11 项通过。真实 host 子进程集成验证投递、落库 ACK、SSE 恢复读取和重复投递去重通过；该测试使用协议夹具，不代表真实平台消息已验收。
- 生产 Chrome local 存储适配已注入 bridge factory；访问级别失败时不读写消息，不回退成功。存储适配 2 项测试通过。
- 权限守卫遗漏的 `storage` 白名单已同步，保持严格集合比较，而非放宽权限断言。
- 新增真实 host 子进程聊天交付集成测试；验证提交 ACK 的 seq 与 SSE 回放 seq 一致，重复消息仅有一条事件。未使用真实平台消息。

## 9. 本地查询路由接入

`chat.messages` 和 `chat.conversations` 已注册公共路由与 capabilities。参数走统一聊天 schema，当前 native 必须在线且已登录。查询仅访问当前账号 SQLite，不派发页面定位、平台步骤或扩展 req；未登录返回 `LOGIN_REQUIRED`，离线返回 `EXTENSION_OFFLINE`。真实 host 子进程测试覆盖消息分页、会话查询、非法参数、账号切换隔离和零平台派发。`chat.sync` 尚未注册，不列入 capabilities。
- 页面推送解析器新增对象、base64 JSON、受限 MessagePack 解码，要求稳定平台消息 ID。5 项测试通过，涵盖混合编码、多消息、白名单输出、重复冲突、缺 ID、非法与超限输入。当前仍需接入页面入口和跨 world 消息通道；解析器单测不代表平台协议已真实验收。

## 10. 同步缺口可见性

持久 outbox 达到容量后不得只写扩展本地标记。新增内部 `chat-gap` 通知，账号仍须与当前 native 账号一致；Host 持久记录账号范围缺口并生成 `chat.gap` 事件，重复通知不无限追加。Agent 可通过事件历史或 SSE 看到缺口。原因仅允许 `OUTBOX_CAPACITY` 与 `PAGE_GAP`，不得携带原始帧。缺口仅在明确覆盖的同步完成后清除，尚无此覆盖证据时保持标记。
- 新增页面采集器：逐条保存扩展持久 outbox 成功后才确认页面消息；存储失败不确认该条及后续消息，确认失败允许后续去重恢复。并发采集合并为同一任务。3 项离线测试通过；固定文档的 Chrome 页面适配仍需接入。
- MAIN 入口已在 document_start 安装被动消息队列，避免等首次 API 才观察导致错过页面自己的连接。队列按接收账号绑定，peek 非破坏，持久保存成功后显式 ack；未保存消息在页面销毁时仍可能丢失，该边界通过缺口语义暴露，不承诺页面端持久无损。
- 页面队列与采集器共 9 项定向测试通过，覆盖解析入队、冲突整批拒绝、账号切换、容量和清理。跨 world 固定文档采集适配尚未接入，不据此宣称生产消息已经进入 Host。
- MAIN 产物测试补齐浏览器 `TextEncoder`/`TextDecoder` 与禁止主动构造的 WebSocket 替身。10 项产物测试通过，加载与初始化仍不访问 cookie、不发网络请求。此前回归的产物失败来自 VM 缺少浏览器全局，不是平台网络错误；其余阶段当次已通过，后续源码整合后再完整重测。

## 12. 显式同步实施入口

同步细化以 [单页同步契约](m3-sync-contract.md) 为准。会话列表与历史均需实现，不能以消费被动队列代替同步。当前分配三个独立模块：单页协议与严格结果校验、仅复用现有 socket 的只读 transport、会话与历史归一化。每个模块先单测，再整合到文档锁、Host 调度及页事务；完成前不注册 `chat.sync`。
- 新增 Host 加密续页凭证模块（AES-256-GCM），绑定账号、模式、会话、页大小、固定文档及 runId，拒绝篡改、过期、跨部署和范围变化。2 项测试通过。该模块尚未接入公共同步，不代表凭证已经持久推进或防止平台页重放；后续必须结合 run 页提交记录验收。
- 单页同步协议已实现并通过 6 项测试：两模式严格判别、会话无消息时的独立 schema、anchor 单调推进、明确末页、unsupportedCount、请求页大小和 512KiB 输出边界。公共 `chat.sync` 仍未注册。
- Host 新增同步页原子提交：历史消息复用消息事务语义；独立会话页可保存没有最后消息的会话，不伪造 `chat.message`。页计数及参数/结果指纹与数据同事务保存，重复同页返回已有计数，内容冲突拒绝。页中途失败回滚消息、事件、会话和进度。3 项新增测试与 5 项原聊天仓库测试通过。
- 当前无消息会话的 `lastEventSeq` 用字符串 `0` 表示尚无消息事件；这不是一个可回放的真实事件。后续公共文档需明确该哨兵值，不能声称所有会话必有消息事件。
- 同步只读 transport 和归一化模块定向合计 22 项通过，覆盖同步响应抢跑、固定路由、错误 mid/route、单在途、断线/账号变化/超时后停用、不重发、不关闭页面 socket，以及无消息会话、非文本计数和分页证据。
- 本轮完整回归曾仅类型检查失败（加密凭证索引的 TypeScript 类型约束），已修正并通过类型检查；其余阶段已通过。同步模块仍未接入生产执行与公共路由。
- 公共同步输入新增独立规范化模块：一次推进单页，接受 Host 签发的不透明 cursor，拒绝外部原始 anchor，limit 上限 100；默认等待和最小间隔沿用调度规则。1 项边界测试通过。尚未注册公共能力。
- 内部 `chat.sync.page` 已纳入严格 step 协议与 NativeBridge 固定上下文调用；商品方法仍保持原校验。
- 页面 runtime 同步分支与 MTOP 共用文档锁，同 step 复用结果。聊天超时、迟到成功、账号变化和 runtime 重建均不绕过失败关闭锁。协议、桥接与 runtime 合计 35 项定向测试通过，类型检查通过。
- 页提交支持调用方外层事务，新增回滚用例证明消息数据与公共进度能一起回滚。Host service 正在接入这一原子提交边界，并补合法续页及并发消费测试。

## 13. chat.sync 公共路由接入

`chat.sync` 已注册协议和 Host 路由。每次调用只执行一个 `chat.sync.page`，经过 `chatRead` 调度；首次或续页固定账号、tab/document、模式、session 和页大小。页数据、公共结果、下一页预留在同一数据库事务中提交；同 cursor 并发只允许一个执行，已提交页返回持久结果，attempting/unknown 不自动重放。排队取消不派发，执行后取消返回未知且不提交。

Host 端到端夹具测试 5 项通过；当前测试使用注入的页面结果，不代表真实 Chrome/socket 平台同步已验收。下一步补公共 HTTP 集成和真实只读同步。
- 同步公共路由注册后，协议测试中的旧“chat.sync 不注册”断言已更新为默认参数验证。完整回归正在重新执行；若通过，剩余范围是公共 HTTP 多页集成、真实 Chrome 只读同步及 M4/M5 写能力。
