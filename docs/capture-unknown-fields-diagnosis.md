# 采集信息“未知”排查与修复

日期：2026-10-05。

## 结论与真实验证

卖家、地区、包邮、采集时间显示“未知”的主要原因是目录映射遗漏，并非这些数据无法采集。

本次使用两个 `deepseek-v4.1-flash` 子代理检查采集链路和目录映射。主代理通过 `ego-browser` 读取已配置飞书商品表首页，核对原始记录与商品目录输出。只记录字段计数，不保存原始记录、商品正文或凭证。

| 字段 | 飞书原始记录有值 | 修复前目录有值 | 修复后目录有值 |
| --- | ---: | ---: | ---: |
| 卖家昵称 | 20/20 | 0/20 | 20/20 |
| 地区 | 20/20 | 0/20 | 20/20 |
| 包邮 | 20/20 | 0/20 | 20/20 |
| 采集时间 | 20/20 | 0/20 | 20/20 |

修复前后均查询首页 20 条。扩展完成构建并通过标准“重新加载”加载新版本；未清理配置和商品数据。

## 已修复的问题

1. `mapFeishuRowToCatalogProduct` 未传递卖家昵称、地区、包邮、标签和采集时间。现在读取标准字段和已有别名，并兼容日期与包邮字段的常见数据类型。
2. 自营商品详情补齐未复制卖家昵称、地区；跳过详情的条件也未检查这两个字段。现在缺值时请求详情并补入，保留列表中已有的非空值。
3. 详情地区仅读取 `city`，遗漏了仓库既有详情消费者使用的 `prov`。现在优先读取城市，城市缺失时使用省份。
4. 重复采集时，新响应的空字符串会覆盖已有卖家、地区等文本。现在保留已有非空文本，并同步保护价格、原价和发布时间的配套数值。明确返回的零价仍能更新。
5. 界面将上述缺值显示为“未提供”，悬浮提示说明是飞书记录缺值还是本次闲鱼数据缺值，避免把缺值解释为永久无法获取。

## 仍可能缺值的情况

- 搜索采集默认关闭“同时采集商品详情”。关闭时不会额外采集描述、浏览量、收藏数、类目和全量图片等详情信息；需要这些信息时，应在新采集任务中开启详情采集。
- 详情请求失败时，本次详情字段可能缺失。采集任务通过 `detailFailed` 统计失败；自营商品目录通过 `warnings` 提示补齐失败或超出预算。
- 搜索和详情响应均没有对应字段时，保留空值。现有修复不推测卖家或地区，不把缺少包邮标记直接判定为不包邮。
- 飞书商品标准表和现有写入转换没有“商品描述”和多图字段。即使本地详情采到了这些信息，当前标准飞书写入也不保存它们。这属于存储能力限制，不能据此认定平台无法采集；本次未变更远程表结构。
- 已经被历史采集覆盖掉的数据不会凭空恢复。目录映射遗漏的数据刷新即可恢复；源记录本身缺值的商品需要补充源表或重新采集。暂停任务续跑会按已有 `storedIds` 去重，不会自动重新补齐已存商品。
