# 聊天中心首次同步与发送开关修复

## 问题与原因

聊天中心首次打开可能显示空会话列表。运行时准备原先允许聊天 WebSocket 未建立时返回成功；后续会话同步返回 `NO_SOCKET`，应用启动控制器仍将它标记为完成。聊天页是懒加载页面，也可能错过此前的同步完成通知。

真实浏览器排查确认：闲鱼账号已登录、页面 host 已安装，但同步返回 `目标聊天 WebSocket 尚未建立`。新聊天页建立连接后，同步成功写入 15 个会话。

## 修复行为

- 聊天用途的运行时准备要求 WebSocket 已打开；平台 API 用途保持独立。
- 仅同步结果明确为 `ok: true` 时标记启动完成。失败保留原因，允许重试。
- 打开聊天页时补启动准备与同步；收到后续连接打开事件时自动重试未完成的同步。
- 同步早于聊天页挂载时，订阅者立即读取最新本地缓存。
- 会话列表显示同步失败原因和重试入口。
- 移除「回复／发送已锁定／启用发送」区域。选择会话并输入有效内容后，可以直接点击发送；生成建议不会发送消息。
- 保留消息长度、买家 ID、会话隔离和发送中的重复操作校验。

## 打开时自动建立连接

此前的准备流程只等待 background 收到 `open` 事件。service worker 重启、事件通道尚未就绪或复用扩展更新前的旧页面时，事件可能丢失。旧页面也可能没有安装连接监听。重复等待不会让这些页面重新建立连接。

- 打开工作台后自动准备闲鱼 `/im` 页面；没有聊天页时后台创建。
- 从 MAIN world transport 读取实际连接状态。已有连接直接复用，并同步本地连接状态。
- 新页面先等待闲鱼自身完成登录握手。旧页面没有捕获连接、连接已关闭或等待超时时，自动重载一次，再等待连接。
- 旧页面缺少平台 host 时，同样自动重载恢复 `document_start` 注入。并发准备共享一次恢复操作。
- 准备先检查登录状态。未登录或需要验证码时保留相应提示。平台 API 用途不因缺少聊天连接而重载。
- 每次准备最多重载一次，仍失败则返回真实错误。启动通信超时调整为 90 秒，覆盖首次加载与一次自动恢复。

连接与鉴权继续使用闲鱼原站逻辑。扩展负责启动或恢复聊天页，再复用原站连接。

## 验证

运行根目录 `npm run typecheck`，以及 Workbench 聊天／回复测试、扩展聊天测试、运行时会话测试。通过 ego-browser 检查真实扩展页面。验证过程中未向买家发送测试消息。

自动连接修复后，background 测试 130 项、扩展聊天测试 196 项、Workbench 启动与聊天控制器测试 35 项均通过，类型检查和扩展／工作台构建通过。重新加载扩展后，在真实浏览器确认 `CHAT_RUNTIME_PREPARE` 返回 `socketReady: true`、`socketStatus: open`，MAIN world 连接快照同样为 `open`。重新打开工作台并进入聊天中心，自动显示实时连接已建立，并同步 15 个会话。
