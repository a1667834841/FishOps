# 项目开发与测试规范

本文档适用于 FishOps-Workbench 项目及其 Git worktree，不以目录名区分，其他项目不适用。功能开发、bug 修复、测试和交付前，必须先阅读并执行本规范。

## 0. 按任务风险分路径

先按改动的实际影响初步分级，再选路径；执行中按新证据调整分级。不能仅凭代码行数判断风险。

- **A 微小任务**（文档、错字、不改行为/接口/权限/状态的静态文案）：定向读相关片段 → 修改 → 核对内容一致性与 diff。纯文档变更不运行应用测试、typecheck、build 或浏览器；源码里的静态文案不默认跑 E2E。交付产物仍要构建受影响包；一旦出现布局或行为风险，升级到 C。
- **B 局部低风险逻辑**（错误与输入明确、可单测，不涉及安全、权限、跨系统或外部写入）：定向确认调用契约 → bug 修复前先得到失败回归 → 最小修复 → 补齐相关边界 → 跑必要受影响检查。按真实契约选边界，不加无关用例，不做全仓扫描，不启动浏览器。重复失败、因果不明或影响范围扩大时，先报告新证据并扩大必要诊断；仅出现页面或集成影响时升级到 C，涉及高风险时升级到 D。
- **C 页面、扩展与集成**（DOM、组件、store、路由、扩展 API、初始化等）：从真实入口取证 → 建立失败回归 → 修改 → 相关检查 → 用原流程复测；使用子代理时，优先由同一执行子代理完成该闭环，或按 AGENTS 统一约定不重复派工。遵循现有 `npm run agent:setup` 与外部副作用规范，不遍历全部页面。真实入口不可用时如实标注阻碍，不得用 Mock 页面替代。
- **D 高风险变更**（权限、安全、持久化、迁移、跨系统、删除、真实写入）：先取得明确授权并准备恢复方案，再按实际影响扩大验证范围。

**完成条件**：验收条件和必要检查通过，且没有未解释的失败，即可返回；无关发现记入后续事项。同一错误没有新证据不重复尝试；范围需要扩大时先报告风险。

## 1. 运行入口

- 优先使用已确认的项目真实入口；必要时查 `package.json` 的 `scripts`、`main` 与构建配置，确认 dev 入口和实际 dist 目录。
- 记录刷新方式：改代码后是热更新还是重新构建，插件与工作台分别如何重载。
- 用户反馈“没生效”时，先确认新代码是否被加载（入口、产物、缓存、重载动作），再排查逻辑。
- **禁止为了测试功能临时创建** `mock.html`**、**`test.html`**、**`demo.html` **等页面模拟真实工作台或插件环境。**
- 页面、组件、路由、DOM、store、插件集成等问题，应直接通过项目真实运行入口验证。

## 2. 验收场景

- 用“用户动作 → 状态变化 → 可见页面/组件 → 副作用”四段式描述每个场景。
- 按变更行为选择场景：
  - 纯函数、校验、数据转换：单元测试即可。
  - 简单输入问题：至少覆盖原触发、合法输入、非法/空值和再次操作。
  - DOM、组件状态、store、路由、生命周期：通过真实组件或真实应用入口验证。
  - 初始化、计时、生命周期或导航状态：覆盖初次进入、计时结束、切出再进入等对应场景。
- 列表首页不等于展开折叠：首屏加载与逐条展开/收起要分别验证。
- review 按场景逐项复核证据，不以测试数量代替场景证据。
- **Mock 页面产生的行为证据不能作为真实 E2E 验收证据。**

## 3. 测试分层与行为测试

### 3.1 单元测试

以下问题优先直接使用单元测试：

- 纯函数
- 参数校验
- 数据转换
- 格式化
- 状态计算
- 独立工具函数
- 明确且局部的输入边界问题

允许 mock 函数、模块、请求结果或输入数据。

这类测试不需要：

- 启动浏览器
- 创建 Mock HTML
- 构造假的完整页面
- 模拟整个工作台环境

### 3.2 页面与 E2E 测试

每次执行 E2E 前都必须在**当前 worktree 根目录**运行 `npm run agent:setup`，并确认退出码为 0 且输出包含 `SETUP_COMPLETED`。这包括修改后的复测和切换 worktree 后的测试。该命令会构建当前代码、同步到 `~/.fishops/agent-extension`、重载固定目录插件并导入本地配置。命令失败时不得继续 E2E；应记录失败原因和阻碍。开始测试已有闲鱼页面前，刷新页面以加载新的 content script，并确认闲鱼账号仍处于登录状态。详细流程见同目录的 [Agent 测试环境说明](agent-testing.md)。普通单元测试和静态检查无需运行此命令。

涉及以下行为时，应从**项目真实入口**测试：

- DOM 绑定
- Vue 组件交互
- store 状态传递
- 路由切换
- 页面初始化
- 插件与工作台联动
- 浏览器 API
- 扩展 API
- 用户反馈“页面没生效”
- 下层单元测试无法复现的问题

**禁止使用自建 Mock HTML 页面替代真实应用入口。**

E2E 中允许 Mock 的是**边界依赖**，而不是被测试的页面本身，例如：

- Mock API response
- Mock 发布接口
- Mock 第三方服务
- Mock 外部写入
- Mock 不稳定或不可控的远端依赖

页面、组件、路由和应用运行环境仍应使用真实项目代码。

### 3.3 Bug 修复

- bug 修复先建立“失败可执行的复现”，确认修复前失败，再修改代码，再复测通过。
- 能通过单元测试稳定复现的局部问题直接走单元测试，不额外创建 E2E Mock 页面。
- DOM、集成或真实运行环境问题必须从真实入口复现。

### 3.4 真实运行故障闭环

浏览器、扩展或 API 故障优先从真实入口收集：

- request / response 结构
- 错误码
- `lastError`
- 耗时
- 必要后台日志
- 当前运行入口
- 当前加载资源版本

拿到真实失败证据后，再建立最小失败回归并修复。

Mock 差异不能单独作为 Chrome、扩展或 SDK 根因证据，也不能代替真实入口验收。

无法取得真实证据时，记录：

- 当前阻碍
- 已证实事项
- 未证实事项
- 待用户验证内容

只读取必要证据并脱敏，不读取或输出 token、cookie。

### 3.5 外部副作用

发布、发送、删除、修改远端数据等外部写入默认使用 Mock，避免真实副作用。

如果测试的是 UI 流程：

**真实页面 + Mock 外部接口**

而不是：

**Mock 页面 + Mock 接口**

除非用户明确授权，否则不得触达真实发布通道。

### 3.6 类型、状态与生命周期

- 类型错误使用调用点真实运行时输入复现，不能只测试 TS 声明或初始字符串 fixture。
- 例如 Vue `type="number"` + `v-model` 可能产生 `number`，应覆盖字符串、数字、空值与非法值。
- 生命周期与倒计时使用状态/组件测试配合 fake timer，不依赖真实等待。
- 字符串断言只检查结构、关键字段，不断言易变完整文案。
- 涉及 props、store、controller、订阅或在途请求时，核对状态传递与清理。
- 局部纯函数修复不扩展成无关的生命周期或浏览器测试。

### 3.7 浏览器环境异常

浏览器空间不可用时确认一次。

之后：

1. 可以使用安全隔离的真实项目环境则继续验证。
2. 无法使用真实入口则标记“待真实环境验证”。
3. 不得因为浏览器不可用而自行创建 Mock HTML 作为替代验收。
4. 不循环探测同一个已经确认失效的入口。

## 4. 验证范围与执行次数

验证顺序：

**失败回归 → 相关测试 → 必要 typecheck → build → 必要真实入口验收**

- 简单纯逻辑问题只运行相关单元测试及必要检查。
- 页面行为问题才执行对应组件测试/E2E。
- 不因为“可能更保险”默认启动完整 E2E。
- 不为了 E2E 创建独立 Mock HTML。
- 最终改动完成后，对受影响 workspace 执行必要的测试、typecheck 和 build。
- 共享代码、协议或跨包依赖变更时扩大验证范围；影响无法隔离时才执行全仓检查。
- 每项大范围检查最终修改后执行一次；后续代码变化或检查失败时，只重跑受影响检查。
- **检查复用**：记录每项检查对应的代码状态、工作目录和覆盖范围；review 未改动代码时直接复用已有结果，后续仅重跑受影响的检查。检查失败、相关代码变化或运行环境影响其有效性时才重跑。复用不削弱第 3.2 节每次 E2E 前运行 `npm run agent:setup` 的要求，也不替代第 5 节的交付构建。
- 独立检查可以并行；依赖构建产物的验收必须在构建完成后执行。
- 每条命令记录退出码和结果摘要；输出过长时保存日志并读取汇总，不因输出截断重复执行。
- 仅修改文档时检查内容一致性和 diff，无需应用测试、typecheck 或 build。

## 5. 构建交付

- 代码变更交付前必须实际构建受影响包；测试和 typecheck 不能代替 build。
- 用户运行 dist 时，先确认现有构建脚本和实际加载目录，并确认新资源已经生成。
- 按入口要求刷新或重开工作台，必要时重载插件或刷新宿主页。
- 刷新前确认不会中断用户正在运行的任务，否则先征得同意。
- 页面相关修改必须尽可能通过真实入口复测原流程。
- 无法运行真实环境时明确标注“待用户验证”，不能以 Mock HTML 测试结果代替。

## 完成清单

- 运行入口与刷新方式已确认
- 每次 E2E 前已在当前 worktree 执行 `npm run agent:setup`，退出码为 0 且包含完成标记
- 测试层级选择正确：简单逻辑使用单元测试，页面行为使用真实入口
- 未使用临时 Mock HTML 冒充 E2E 验收
- 失败复现先行，修复后复测通过
- E2E 中仅对必要外部依赖或副作用进行 Mock
- 必要测试、typecheck 与 build 已执行（纯文档变更不适用）
- 构建产物已生成
- 实际加载已确认，或明确标注“待真实环境验证”
- 按“已修改 / 已测试 / 已打包 / 实际验证或待验证”分层汇报
