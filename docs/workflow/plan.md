# plan：思考计划

AI 默认完成实现、测试、Commit、Push、PR、CI 及审核意见处理，不逐步询问；用户负责澄清和 Review。只读或交付限制按用户要求。

读取需求、代码与测试，按影响分级：

- A：文档、错字、无行为变化的静态文案。简要确认范围即可开发；布局变化升 C。
- B：契约明确、可单测的局部低风险逻辑。确认调用契约、根因及回归范围后开发。
- C：页面、扩展、store、路由、初始化或集成。先从真实入口取脱敏证据，写实施步骤及验收计划。
- D：权限、安全、持久化、迁移、跨系统、删除或真实写入。先核对授权、风险与恢复方案，再制定计划。

验收写成「动作 → 状态 → 可见结果 → 副作用」，覆盖正常、边界、再次操作与清理。页面明确触发、位置、尺寸、比例和交互可达性。

关键需求歧义、重大架构调整、数据安全风险或新增未授权操作，先完成可独立调查，再请用户决策；已有授权不重复询问。

范围、验收及副作用边界明确后进入 coding。执行中出现新证据时调整分级与计划。
