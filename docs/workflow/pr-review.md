# pr review：等待人工审核

- 自查需求、diff、回归及文档一致性，运行 `git diff --check`；清除密钥、本地配置及无关改动。
- 按[test](test.md)判断普通或 Draft PR，完成 Commit、Push、创建 PR；有 Issue 时关联，已有 PR 时更新。PR 关联到 Orca 工作区并读回确认。
- 标题与开头说明一个明确问题及改后行为。正文以 5～8 行为目标，含验证、Issue；复杂改动补设计与风险。
- 详细证据放链接或折叠区；页面改动展示最终真实截图。受环境阻碍缺图时仅交付 Draft PR 并说明。正文列出阻碍、未验证项，本地与 CI 分开写。
- 末尾写「总结结论」，依据实际证据说明目标与阻碍。
- Push 或 GitHub 异常最多尝试三次；Git 冲突最多同步主分支并安全解决一次，仍失败报告人工处理。

跟进 CI，修复任务相关失败后更新原 PR。交付结果、验证结论、PR 链接与待办，等待人工 Review，不自动 Merge。审核意见回 coding；Draft 补齐验收后转普通 PR。确认合并后进入 done。
