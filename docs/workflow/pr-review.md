# pr review：等待人工审核

- 自查需求覆盖、diff、回归范围及文档一致性，运行 `git diff --check`；清除密钥、本地配置及无关改动。
- Commit、Push，创建关联 Issue 的 PR；已有 PR 时更新，不重复创建。PR 关联到 Orca 任务工作区并读回确认。
- 标题与开头说明一个明确问题及改后行为。普通正文以 5～8 行为目标，包含验证、关联 Issue；复杂改动补关键设计与风险。
- 完整命令、日志、验收步骤放证据链接或折叠区；页面改动直接展示最终真实截图。正文列出阻碍、未验证项，本地与 CI 状态分开写。
- 末尾写「总结结论」，依据实际证据说明目标与阻碍。
- Push 或 GitHub 异常最多尝试三次；Git 冲突最多同步主分支并安全解决一次，仍失败报告人工处理。

交付结果、验证结论、PR 链接与人工待办后停止，等待人工 Review，不自动 Merge。收到修改意见回 coding，再测试并更新原 PR；确认合并后进入 done。
