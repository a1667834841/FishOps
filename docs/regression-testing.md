# 回归测试

回归测试用于检查修改某个功能后，其他关键功能是否仍可用。先运行定向测试，再按[开发与测试规范](development-testing.md)的路径交付：纯逻辑运行本地全量回归；页面、扩展与接口改动运行完整回归，再补真实业务验收。纯文档改动使用快速路径。

## 常用命令

| 命令 | 覆盖范围 | 所需环境 |
| --- | --- | --- |
| `npm run regression` | 全量单测、类型检查、构建、安全检查、Bridge 冒烟、采集闭环和 Service Worker 启动检查 | Node.js、项目依赖 |
| `npm run regression:e2e` | 任务空闲检查、`agent:setup` 部署、真实页面与接口回归 | ego lite、已加载固定目录插件、本地 AI/飞书配置 |
| `npm run regression:full` | 依次执行以上两层 | 同上 |
| `npm run test:regression` | 回归编排脚本自身的单测 | Node.js |

在当前 worktree 根目录安装依赖后，按影响选择一个入口：B 路径运行 `npm run regression`；C / D 路径运行 `npm run regression:full`。后者已包含本地回归，无需先重复运行前者。

本地全量回归与 `npm test` 的关系：`npm test` 是全量单测；`regression` 还包含类型、构建、安全和产物检查。不需要手工重复运行两者。

完整回归的真实阶段再次运行 `agent:setup`。这是当前项目要求的 E2E 部署门槛，不能用前面的普通构建替代。首次加载、登录、授权或浏览器不可用时，真实阶段失败，报告中保留未完成状态。

## 已维护的真实用例

| 用例 | 动作与结果 | 边界 |
| --- | --- | --- |
| Bridge | 扩展内页发送 `PING`，取得 PONG | 不替代闲鱼平台连接验收 |
| 任务列表 | 读取现有任务，返回数组 | 不创建、暂停、取消任务 |
| 聊天缓存 | 读取现有会话，返回数组 | 不发送消息，不证明实时消息已同步 |
| 发布历史 | 读取现有发布任务，返回数组 | 不创建或提交发布任务 |
| 7 个主页面 | 点击顶部导航，检查目标页面内容、标题和选中状态 | 覆盖页面加载；不代表所有页面交互通过 |
| AI 连接 | 在设置页点击「测试 AI 接口」，显示真实接口测试成功 | 一次固定提示词请求，可能产生少量模型费用，不发送业务上下文 |
| 飞书连接 | 在设置页点击「测试飞书连接 (Schema)」，显示结构读取成功 | 只读取表格结构或数据表列表，不写入表格 |

每个用例必须执行，缺配置不能算作跳过后成功。页面加载失败、按钮不可用、请求错误、超时均计为失败。没有运行中任务才允许部署；发布中心的待执行草稿不属于运行中操作。执行期间不要启动任务，多个 worktree 不得同时使用固定测试插件。当前按串行流程执行。已有锁保持原样，本轮不扩展并发控制。

本地 JSON 默认沿用主工作区的 `agent-config.json.local`。AI 的 `baseUrl` 应填写 API 根路径，例如 `/v1`，不能写成 `//v1` 或包含 `/chat/completions`。每日采集模式无需 `productTableId`，可从 JSON 移除。由于配置导入采用 PATCH 合并，移除 JSON 字段不会清除浏览器里已有的旧表 ID；旧配置迁移时须先在设置页清空旧商品表 ID。`reply` 必须显式设置 `enabled: false`、`mode: "suggest"`，防止真实回归触发自动发送。

## 结果与故障定位

每次执行生成 `.regression/<时间>-<进程号>/report.json`。报告包含 worktree、提交号、未提交改动标记、检查结果和耗时。面向人的交付摘要只写结果、验证是否通过与需人工处理的阻碍，并给出证据链接；完整检查明细供需要时查看。普通检查的完整输出放在同目录日志中。浏览器原始输出不保存，只记录本脚本生成的脱敏结果；不记录凭据、聊天正文和完整服务端响应。报告目录被 Git 忽略。

退出码 `0` 表示选定层级全部通过，`1` 表示失败或阻碍。本地独立检查继续收集失败；构建失败后，不执行依赖产物的检查。任一本地检查失败时，完整回归禁止进入真实部署。

E2E 失败时，报告保留测试空间 ID，便于在同一空间检查。用户接管或停止时，不得自动改用新空间。用户已授权恢复本项目部署脚本主动结束的测试空间以继续同一任务；用户实际接管或停止时，等待明确恢复指令。使用 `FISHOPS_REGRESSION_SPACE_ID=<ID> npm run regression:e2e` 复用空间。CI 仅运行本地全量回归，并保存报告与日志；CI 不具备本机账号和凭据，不执行真实 E2E。

## 如何增加回归用例

集中维护清单位于 `scripts/regression-cases.mjs`：

1. 页面入口加入 `pages`，提供导航文字、标题和目标页面选择器。
2. 已有数据读取加入 `commands`，提供命令、最小 payload 和结果数组键；避免返回业务正文到报告。
3. 设置页连接测试加入 `connections`，提供分区按钮、测试按钮、所属表单控件和成功提示。
4. 新的多步场景在 `scripts/regression-browser.mjs` 中通过 `check()` 注册；使用真实入口、可观察状态与明确断言，不用固定 sleep。

修复 Bug 时，同时补充对应模块单测，并将适合重复执行的真实场景加入清单。涉及筛选、分页、图片预览、任务恢复等功能时，还要按需求执行专项真实验收；目前这组 E2E 基线不能替代所有业务场景。外部写入按开发与测试规范第 5.3 节核对授权。测试账号发布商品已有授权，发布链路改动须执行专项真实验收；默认回归清单仍保留只读与连接基线，不在每次无关修复中重复发布。其他写入按实际授权执行。
