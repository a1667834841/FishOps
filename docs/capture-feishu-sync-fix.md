# 采集按日同步飞书与商品库读取

## 原因

原实现把采集同步和商品库读取绑定到一个商品表。表中缺少「商品描述」时，同步只能暂停并要求手动补字段。采集关键字只保存在任务断点中，没有进入飞书记录。恢复同步按商品 ID 读取本地最新内容，还可能把后续采集的数据当作旧任务结果。

## 修复后的行为

- 采集完成后，根据原始采集时间，按北京时间写入同一多维表格内的 `商品采集_YYYY-MM-DD`。
- 先查询数据表列表。没有当日表时创建，并提供完整标准字段；已有表则追加。每天只有一张采集表。
- 自动补充缺失字段，包括「商品描述」和「采集关键字」。已有字段类型冲突时停止，提示手动调整；不修改类型、不删除字段。
- 唯一键为「商品 ID + 北京时间采集小时 + 当次关键字」。相同键跳过，即使价格或描述变化也不覆盖；不同小时或不同关键字分别保存。
- 按 200 条分批写入。去重读取失败时停止，不把读取失败当作空表。响应丢失后，恢复时先查已有记录，再补写缺失记录。
- 同一扩展的同步操作串行执行。飞书记录没有该组合键的唯一约束，多个独立客户端同时写入仍可能产生重复，不能把本地串行化视为跨客户端锁。
- IndexedDB 保存当次完整商品快照，任务断点只保存引用。后续采集即使覆盖本地目录，旧任务重试仍使用原始内容、时间和关键字。
- 同步成功后才将任务设为已完成，并显示新增数量和跳过数量。
- 配置缺失、类型冲突或接口失败时暂停任务，保留本地商品和断点。修复后点击“恢复”补做同步，已完成的页面不重复采集。昨天采集、今天重试的数据仍进入昨天的表。
- 暂停或取消后不再发起后续批次。已经发送的飞书请求可能完成，恢复时通过去重避免重复写入。
- IndexedDB 不可用时回退内存；内存记录不能保证跨 Worker 重启恢复。

## 商品库

- 只读取北京时间今天和昨天的每日采集表；旧商品表保留，不迁移、不纳入商品库。
- 展示全部采集记录，不按商品 ID 合并。默认按完整采集时间倒序排列。
- 增加「关键字」列；搜索支持采集关键字、商品标题和商品 ID，由飞书服务端执行包含匹配。
- 每张表使用真实分页，只合并最多两张表的分页缓冲，不拉取全部商品再分页。总数仅在服务端提供时汇总。
- 每行保留真实来源表 ID。查看素材、创建发布任务和填表前都验证该表属于当前多维表格的每日表或旧配置表。
- 分页游标绑定配置、日期范围和查询条件，保留 10 分钟。Worker 重启、跨日或游标过期后需刷新商品库。

## 验证

测试覆盖建表与补字段、同小时跳过、不同关键字新增、响应丢失后恢复、跨日与 Worker 重启后的原始快照读取、跨表分页排序、关键字搜索、来源表读取和取消后停止写入。测试使用模拟 HTTP，不写入真实飞书。

## 使用

重新加载构建后的扩展并刷新工作台。配置 App ID、App Secret 和多维表格 Token 后即可采集；无需先手动创建商品表。设置中的旧商品表 ID 为可选项，仅用于旧表分析和手动导出。

应用需具备数据表列表、创建数据表、读取与创建字段、读取与创建记录的权限，并有目标多维表格的编辑权限。创建数据表可使用 `base:table:create` 或 `bitable:app` 权限，具体以飞书当前权限配置为准。

飞书每个多维表格的数据表与仪表盘总数上限为 100。达到上限后同步暂停，提示整理表格，不自动删除历史表。近两天只是商品库的展示范围，历史每日表继续保留。

更新前的任务没有完整快照，无法保证还原当时的描述、时间和关键字。这类任务会明确提示重新采集，不使用本地最新数据伪装为旧任务。旧已完成任务也不会自动补同步。

官方接口参考：[列出数据表](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table/list)、[创建数据表](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table/create)。
